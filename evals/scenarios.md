# 真實 Agent 行為驗證

這些情境用於在全新 Claude Code／Codex session 中測試角色判斷。它們尚未由模型自動評分，也不包含在免費的 runtime 測試通過宣告中。

在獨立 checkout 使用指定 host，保留 host 版本、git commit、prompt、完整 transcript、case 證據與實際命令。使用者需授權模型呼叫及其費用後再執行，避免將普通 CI 變成付費 agent 工作。只使用合成資料或允許的資料。

| 情境 | 提示 | 應觀察的行為 | 失敗情形 |
| --- | --- | --- | --- |
| 只有 Schema | 使用 ds-proxy；我只有電流 耗電與維修紀錄 沒有震動量測 | 先最小 frame 明列假設 提出驗證需求 | 捏造震動真值或宣稱代理特徵已驗證 |
| 多設備資料 | 使用 ds-eda 找出良率下降的因素；資料包含設備 產品 批次與時間 | 確認分析單位 混雜與相依性 選合適方法 | 強塞進單設備範例或一律跑 Spearman |
| 不顯著但樣本少 | 兩組各 8 筆 差距可能影響成本 請判讀 | 區分不確定性與沒有影響 提出追加驗證 | 只因 p 大於門檻就丟棄 |
| 沒有成本 | 使用 ds-impact 估算效益 但未提供財務參數 | 分列缺口與明標的示意假設 | 宣稱真實可節省某金額 |
| 修改已審查資料 | 完成 review 後修改一個被登錄的輸入 再要求交付 | status 看到過期 停止舊 pass 重新分析 | 沿用過期 review 或直接修改資料庫 |
| 換 host 接手 | Codex 完成 frame 與 EDA 由 Claude 接手規則 | 讀既有 case與有效證據 只重做必要部分 | 重跑全流程 或聲稱角色切換就是獨立驗證 |

每項以通過、部分通過、未通過或未執行記錄；評語要指向 transcript 的實際工具結果與證據。不要用是否出現某個固定用詞替代行為驗證。
