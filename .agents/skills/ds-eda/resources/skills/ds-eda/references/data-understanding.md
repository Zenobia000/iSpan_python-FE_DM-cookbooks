# 資料理解與分析可行性

第一次接觸資料、來源或 Schema 改版，或結果出現不合理變化時讀取。目的在確認資料代表什麼、能回答什麼，避免直接把欄位丟進檢定。

## 先建立資料契約

| 問題 | 要保存的內容 |
| --- | --- |
| 一列代表什麼？ | 人、交易、批次或感測紀錄；唯一鍵、重複紀錄與重複量測的差別 |
| 指標怎麼量？ | 結果與事件定義、單位、觀測窗口、分母及量測限制 |
| 何時可取得？ | 事件時間、登錄時間、資料延遲、決策時點及可用窗口 |
| 有哪些資料？ | 來源、版本、涵蓋期間與族群；各檔案粒度與關聯鍵 |
| 哪些比較做得到？ | 各群樣本與事件、產品／設備重疊、時間覆蓋及缺口 |
| 哪些資料可使用？ | 開發／保留範圍及本題允許的讀取與輸出位置 |

## 最小品質檢查

檢查型態、單位、時間排序、唯一鍵、分布、缺值、重複與合理範圍。數字代碼可能是類別；不依欄名自行猜測單位，或把負攝氏溫度當成通用錯誤。

缺值需看群組、時間與結果可取得情形；沒有足夠依據時不要宣稱缺失機制已確定。離群值先檢查量測、事件與模式，依業務意義決定保留、修正或另做敏感度分析。不能只因固定缺值比例或 IQR 門檻就自動刪除。

Join 前核對鍵的唯一性與預期關係，join 後比較列數、有效單位、事件數及分母，檢查多對多膨脹和來源族群差異。沒有可比較群組時，把結論限制在可觀測範圍。

## 洩漏與探索邊界

先保留獨立資料，再做目標導向特徵篩選、轉換參數估計或門檻調整。學習參數只在訓練範圍或訓練折估計；本題特徵亦須在決策時可得。[scikit-learn 洩漏指引](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)

記錄哪些資料已被查看、用於假設生成或調整。資料欄位結構可先盤點，但不能看過驗證結果後仍稱為未使用的驗證。

## 本輪需要留下什麼

保存 Schema 與資料來源說明、品質摘要、排除與轉換紀錄、分組覆蓋及不能回答的問題，連到資料版本與程式。品質足以支援問題時就進入有目的的比較，不為完成清單畫所有欄位組合。

方法背景：[特徵工程系統化分析指南第 6–7 頁](https://github.com/Zenobia000/iSpan_python-FE_DM-cookbooks/blob/feat/agentic-decision-analysis/docs/references/%E7%89%B9%E5%BE%B5%E5%B7%A5%E7%A8%8B%E7%B3%BB%E7%B5%B1%E5%8C%96%E5%88%86%E6%9E%90%E6%8C%87%E5%8D%97.pdf)。重複或時間量測另讀 [相依資料](dependent-data.md)。
