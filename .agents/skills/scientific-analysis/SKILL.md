# Scientific Analysis

以專家與 agent 的研究往返為主介面。先解釋資料與模型行為，再比較提高性能的收益。HTML 是共同檢視證據的產物，不是獨立平台；不需 MCP server。

## 開始分析

先讀既有研究問題、資料字典及前次 run。只詢問會改變有效性判斷的未知：觀測單位、目標／用途、群組或時間結構、資訊取得時點。可執行的部分繼續進行，其餘記錄假設與限制，不無限追問。

先建立分析規格，再呼叫腳本。由 repo root 執行：

```bash
uv run --extra harness python .agents/skills/scientific-analysis/scripts/run.py --help
```

實際欄位及命令參數以 CLI help 與隨附 example spec 為準。需要方法選擇時才讀 [methods.md](references/methods.md)；需要完整研究往返及驗收時讀 [research-workflow.md](references/research-workflow.md)。

## 六種能力

1. **問題與假說**：記錄分析對象、用途、觀測單位、候選解釋及反駁條件。探索後形成的假說另行標記。
2. **資料體檢**：檢查型態、量綱、缺失、重複、範圍、群組、批次與時間。清理不以方便建模為唯一理由。
3. **探索與統計**：按問題選分佈、分面、關係與多變量圖，不盲目堆圖。區分觀察、模型關聯與機制假說。
4. **特徵工程**：記錄公式、單位、資訊可用時間及缺失／零分母處理。需學習的轉換只 fit 訓練 Fold。
5. **建模與驗證**：保留簡單基準與性能候選。同一模型比較新舊特徵，同一特徵比較模型；採相同列與切分。
6. **研究結論**：列支持、反對及未能區分的解釋，允許無改善、無穩定群組、尚待確認等結果。

能力可以回訪，不強制每題走完全部階段。正式支援範圍以腳本實際提供的 task／stage 為準，不把方法卡或未實作介面當成已執行能力。

## 人機邊界

- 專家決定問題、欄位含義、領域合理性、採納假說及最終模型取捨。agent 不代簽研究決定。
- 原始資料唯讀。每次新分析寫新 run；不覆蓋已交付證據，不偷換資料或生成合成 Kaggle 資料充數。
- 不把 row ID、病人、批次或未來資訊當捷徑特徵。無法證明獨立性時揭露限制。
- 調參、特徵選擇及採樣策略不得透過反覆查看最終測試結果決定。小樣本不機械保留固定比例 Holdout。
- 可預測不等於機制成立；係數、相關性、群組、SHAP 或異常排名均不自動提供因果證據。
- 分群／異常沒有標籤時，不宣稱準確率或已找到 root cause。穩定性與領域用途分別檢查。

## 與互動圖表往返

先選能回答當前問題的少量圖組。每組說明：**觀察 → 替代解釋 → 限制 → 下一步**。
保留全體參考、單位、樣本數與抽樣說明。高亮與篩選不可混稱；改變篩選不表示模型已重新估計。

專家從 HTML 匯出檢視條件與註記後，先用 `resume` 驗證資料 hash、run 與樣本識別；不相符就拒絕套用。
依註記提出新的分析假說／子群比較，再執行新 run。原結論保留，不把第二輪探索回填為事前預測。

## 交付前

- 對照真實 metrics 與圖表數據，不手寫或推測提升。
- 分開展示可解釋基準、性能候選、逐 Fold 結果及代價；不自動替換模型。
- 記錄來源版本、程式／環境、參數、選取條件、排除規則與產物索引。
- 缺資料、驗證失敗或未檢視圖表時如實說明；檔案存在不等於數值與視覺驗收通過。
