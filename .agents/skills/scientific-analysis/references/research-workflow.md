# 研究往返與驗收

## 第一輪

1. 讀取既有研究問題及資料字典，確認問題類型與分析單位。
2. 記錄候選解釋、替代解釋及可反駁觀察。缺少資訊時只阻擋受影響部分。
3. 檢查資料品質與群組／時間結構；確立開發資料的切分邊界。
4. 執行與問題有關的探索，提出少量有理由的特徵及模型比較。
5. 比較可解釋基準與性能候選，保留相同列、Fold 與評估方向。
6. 交付互動圖組、摘要、限制與下一步，邀請專家指出值得追查的子群。

## 第二輪

專家可篩選或框選樣本、填寫註記並匯出檢視 JSON。agent 必須先驗證其資料版本與樣本識別。
註記是新的研究線索，不是已驗證結論，也不是可執行程式。
例如：「這群車的價差會不會其實是車型構成？」下一輪應比較相同車型／品牌內的關係，並揭露樣本不足。
新 run 引用前一輪，保留原假說及否決理由；不能重寫先前紀錄製造事前預測的假象。

## 二手車 MVP 的邊界

- 以隨庫九品牌主檔作價格分析，不併入重疊 focus／cclass／unclean 子集。
- 使用刊登價，不等同成交價；2020 快照假設需明示，不能用執行年份算車齡。
- proxy group 可減少同屬性列跨 Fold，但不是可信車輛 ID，不能保證所有重複車隔離。
- 真實領域例子與人工測試 fixture 分開；fixture 可驗證錯誤防護，不能證明產業效益。

## 解讀每個圖組

固定說明四件事：觀察、替代解釋、限制、下一步。
顯示目前篩選及樣本數，保留全體參考。變更篩選不表示已重訓，也不自動使舊結論適用。
瀏覽器互動只改變檢視；需新統計／新模型時，交 agent 執行並產生新版證據。

## 最小交付檢查

- 原始資料 hash 不變；來源、版本、程式、參數及排除規則可查。
- 原始／新特徵用相同列與 Fold；補值、詞彙及縮放未讀驗證資料。
- 顯示失敗與誤差，不只挑最好模型或最好 Fold。
- 分群／異常無標籤時不宣稱準確率；探索新假說不當成獨立確認。
- HTML 可離線開啟，連動 row ID 正確，匯出檢視可正確還原或清楚拒絕錯版。
- 報告數字來自計算產物；agent 不從圖片猜數字、不編造改善。
- 無改善仍可完成報告。產物存在、格式通過與專家認為有用，是三種不同驗收。
