# 時間 群集與重複量測資料

同一客戶、設備、批次或地區出現多列，或資料沿時間連續量測時讀取。先判定哪些觀測能視為獨立，再處理推論與驗證。

## 先辨認結構

列出獨立單位、每單位列數、群數、時間間距、共同環境及可能相關的事件。同一設備的一千筆感測值，不等於一千台獨立設備；要估計哪種族群的效果，決定了適合的分析單位與加權方式。

一併檢查裝置／客戶內相關、共同時間衝擊、缺值與不規則取樣。不要把原始列數標為有效獨立樣本數，也不要假裝能以通用公式得到所有設計的有效樣本數。

## 依問題調整方法

- 若目標就是設備或客戶層級，可以先形成有意義的單位摘要，再比較；摘要會改變估計目標及資訊量，需說明。
- 若需保留列層級資訊，可評估群集穩健推論、GEE、階層或時間模型；依群數、設計與模型假設判斷，不因套件能執行就宣稱區間可靠。
- 重抽樣須反映設計：群集資料評估按群抽樣，時間資料評估適合的區塊或其他相依重抽樣。不能直接對所有列做一般 bootstrap 便認為已處理相依性。

GEE 可處理群內可能相關、群間獨立的部分重複或群集量測情境，仍需選擇合適的平均與相關結構。[statsmodels GEE](https://www.statsmodels.org/stable/gee.html)

## 驗證與特徵時間

驗證策略取決於上線情境：預測既有設備未來結果時，保留後期資料；要泛化到新客戶或新設備時，評估群組隔離。必要時同時約束時間及群組。

時間窗只能使用決策當下已到達的資料。評估滾動窗口重疊、標籤觀測窗口及資料延遲是否造成跨切分污染；依本題窗口決定間隔，而非套用固定 gap。

## 必備回報

列數與獨立單位數分列，呈現群數、每群規模、時間範圍、切分與相關性處理。若群數或事件不足，縮小主張、提供描述性結果或補資料方案，不只加一句限制後繼續沿用失效 p-value。
