# 每輪探勘的開始 回報與接續

開始新一輪 EDA、追查替代解釋或接手既有探索時讀取。AI 承擔研究推論和推薦順序，人類確認問題邊界及需要領域判斷的事項。

## 開始前

先用 status 核對有效 frame、問題確認及 plan，再讀相關假設定義、先前 findings 與本輪需要的證據。缺少確認或計畫時回到 ds-frame；不以自行填入同意代替使用者回覆。

寫下本輪要回答的一個問題：對應哪個假設、目前有哪些支持與反對證據、哪個替代解釋最需要排除，以及這次比較將增加什麼資訊。說明推薦方法與順序的理由，避免只列分析選單。

## 本輪執行

1. 在 `reports/explorations/round-001/` 等新目錄保存結果；程式放本題 analysis/，參數放 config/。
2. 從 [inquiry 模板](../../ds-eda/templates/inquiry.md) 建立本輪 `eda.md`，在看到結果前記下問題、預測、分析單位、比較、資料切分與反證條件。模板提示文字須替換為本輪內容。
3. 依計畫計算與繪圖，保存分母、排除筆數、時間與群組條件。缺少結果或計算失敗時如實保留，不用推測數字補空格。
4. 結果及狀態寫入 research/findings.md，引用本輪證據；不依結果回改 plan 綁定的 hypotheses.md。
5. 新切角標為探索；若準備正式採用新研究設計，更新計畫並核對受影響下游。

每輪詳細產出可以保留；正式 stage 登錄的是可供後續使用的證據文件。現有 runtime 每個 stage 管理一個當前版本，重新登錄 EDA 可能使 rules、impact 與 review 過期。

## 對人類回報

先回答本輪問題，再交代證據與限制，最後提出有理由的推薦下一步：

```text
本輪回答：目前支持什麼、還不能回答什麼。
依據：效果與不確定性、樣本及群組、圖表和計算路徑。
其他解釋：已排除、尚未排除與資料無法檢查的部分。
推薦下一步：先做哪一項、為何能縮小不確定性、何時停止。
需要你確認：只有會改變問題、資料使用或業務行動的事項。
```

計畫範圍內可以連續執行，不為每張圖重新詢問。若目標改變或要使用新的資料範圍，先呈現修訂後的完整問題並確認。

## 接續與停止

在 handoff.md 記錄目前問題與計畫版本、資料和程式位置、保留資料的使用情形、已否決解釋及下一步。接手時核對這些證據，不因換 session 就重跑全部分析。

證據已足以支援本次決定、影響低於可接受的業務門檻，或現有資料無法區分主要解釋時，說明理由並收斂。不得僅因未達 p-value 門檻就宣稱沒有影響。

操作依據：[研究流程](../../../docs/research-workflow.md)、[共用執行契約](../session.md)。
