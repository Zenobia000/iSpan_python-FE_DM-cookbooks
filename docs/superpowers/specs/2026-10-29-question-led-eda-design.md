# 問題導向 EDA：先提出可選分析，再累積研究證據

日期：2026-10-29。狀態：設計提案，尚未實作；本文件不表示既有 CLI 已具備以下能力。
範圍：問題 brief、資料盤點、分析建議、人類選擇、互動探索、候選特徵交接。
本輪不實作模型推薦引擎、Auto Research、自動調參、MCP server 或常駐網站。

## 1. 要修正的問題

目前 `scripts/run.py` 的 `report()` 把 `spec.question` 填入 `findings.observation`，搭配固定的替代解釋、限制與下一步。
這不是由數據得出的觀察，也沒有呈現選擇分析方法的理由。`explore()` 主要計算欄位摘要和 Pearson 相關矩陣，沒有依研究問題提出分析路徑。
`inspect()` 在初步盤點時就根據 task 產生 CV；`approved_features` 是整包布林值，不能表達人類逐項選擇原始與衍生特徵。
既有報告互動與資料版本防護可保留，但其存在不能代替研究脈絡。

核心改變：由「執行既定階段並展示結果」，改為「提出有根據的分析選項，執行人類選定的分析，根據證據修正問題」。
分析可以完成於理解資料或否決假說，不必走到建模。

## 3. 互動流程與確認點

採問題驅動的動態研究 DAG，不把下列能力解讀為全專案依序執行的階段。
操作可回訪；證據與修訂採版本化、無環的來源紀錄。研究依賴 DAG 不代表變數間的因果關係。
經蘇格拉底角色審查後的兩張流程圖、分支匯合、停止及失效規則，見 [研究 DAG 流程設計](2026-10-29-eda-research-dag-flow.md)。
每個分析只等待自己的必要依賴；暫緩的分支不阻擋無關分析，匯合不代表多份獨立驗證。

3–5 個是提案預設，可依問題縮減；不是硬湊數量，也不自動執行全部。
使用者可一次授權一組分析及時間／計算預算，組內不逐張圖詢問。新研究問題、實質改變比較母體或新增特徵用途時，回到相應決策點。
有些問題沒有事前假說：允許「開放探索」，記錄想了解的現象與用途，不為滿足表單編造假說。

### A. 問題 brief：先確認要理解什麼

由 agent 將使用者原話轉成一頁可確認的 brief，欄位如下：

- 原始需求、分析受眾、將影響哪項決策。
- 主要問題與最多三項優先子問題；完成後應能回答什麼。
- 目的：描述／比較／尋找關係／生成假說／準備預測；可複選，不強迫立刻選回歸或分類。
- 分析母體、每列代表什麼、觀測期間、資料來源與抽樣方式。
- 關注結果、候選解釋、替代解釋、可推翻猜想的觀察；區分已知與猜測。
- 欄位意義、單位、群組／重複量測、時間與資訊可用時點。
- 實務上多大的差異才值得關注；尚未定義可明示未知。
- 範圍、不回答的問題、資料限制、需補充素材。
- 若未來要建模：先決定探索可使用哪些資料，是否需要另外封存測試資料。

brief 狀態為 draft／confirmed／superseded，記錄版本、確認者、時間與確認內容。
agent 不自行寫入人類已確認。確認前可查看 schema、來源說明與必要樣本協助釐清，不進行正式關係探勘。
未知資訊只阻擋受影響的方法：沒有可信病人 ID 可先描述分佈，但不能把多次就診當獨立樣本做檢定。

### B. 資料盤點：讓建議有根據

確認 brief 後做唯讀低成本盤點：樣本數、有效樣本數、型態、量綱、範圍、分位數、缺失、類別基數、重複與群組大小。
輸出 field dictionary 和品質摘要；不把自動型態辨識當作業務定義，不自動補值／刪除離群點。
如果欄位不支持原問題，先指出缺口與可回答的替代問題，讓人類選擇縮小問題或補資料。
若已有封存測試集，盤點／EDA 僅操作明定的探索資料；本次既有二手車示例已看過的資料仍是探索資料，不能事後聲稱其中一部分是未看過的測試集。

### C. 分析建議卡：先說為什麼值得做

每張建議卡必須包含：

| 欄位 | 內容 |
|---|---|
| 問題與關聯 | 要回答什麼、連到 brief 哪一項，為何影響研究決策 |
| 提案依據 | 已知資料結構／盤點事實／領域假說；尚未計算的關係不得寫成發現 |
| 分析設計 | 使用欄位、樣本範圍、比較單位、分層方式、缺失處置 |
| 方法與圖組 | 常見統計方法、圖形及各自回答的子問題，附備選方法 |
| 預期區分的解釋 | 何種觀察支持哪種解釋；何種結果會削弱原猜想 |
| 適用性與風險 | 獨立性、樣本量、時間順序、稀疏組別、混雜與多重探索 |
| 下一步價值 | 結果將如何影響問題修訂、資料需求或特徵提案 |
| 成本及來源 | 快速／較耗時、顯示抽樣策略、方法來源章節與實作狀態 |
| 選擇 | 待選／採用／修改／暫緩／否決，記錄人類理由 |

推薦排序依「與主要問題相關程度 → 能否區分競爭解釋 → 資料是否足夠 → 成本」。不以最小 p-value 或最高相關係數排序。
agent 每輪至少考慮資料品質、邊際關係、條件關係／替代解釋三個觀點；不相關者簡短說明後略過。

## 4. 常見方法選擇：從問題到圖形

這是設計中的方法目錄，不是已實作能力；MVP 選取範圍見第 9 節。

| 切入問題 | 優先圖組 | 常見方法與何時使用 | 必須交代 |
|---|---|---|---|
| 值集中在哪裡、尾部多長？ | Histogram + ECDF；必要時 Q–Q | 中位數、IQR、分位數；比較原尺度／log 尺度 | 分箱、單位、零／負值；不是所有模型都要求原始特徵常態 |
| 缺失／異常集中在誰身上？ | 缺失率分面、群組×欄位熱圖、原始案例表 | 群組缺失比例、IQR／MAD 作為待查標記 | 不能由圖判定 MCAR／MAR／MNAR；標記不等於刪除 |
| 兩個數值有什麼關係？ | Scatter／hexbin + LOWESS；重要群組分面 | Pearson 看線性、Spearman 看單調，搭配關係形狀 | U 型可低相關；離群值、重複量測、混合母體可能扭曲結果 |
| 群組差多少？ | 原始點 + boxplot／ECDF；效果量與區間圖 | 獨立兩組均值差可用 Welch t；多組視設計用 ANOVA／Welch ANOVA；配對資料另用配對分析 | 比較的是均值、分佈或其他量；獨立性與實務差異先於 p 值 |
| 類別與類別是否相關？ | 比例條圖／mosaic + 列聯表 | Chi-square；適合的稀疏 2×2 表用 Fisher exact；Cramér’s V 或比例差 | 分母、期望格數、組別基準、是否獨立 |
| 總體關係是否來自組成差異？ | 相同座標的分面散點、分層效果圖 | 群內相關；有理由時補充探索性線性模型／交互項 | 有重疊樣本範圍才能比較；調整後仍不自動代表因果 |
| 多個欄位是否重複描述同一現象？ | 少量變數散點矩陣 + correlation；必要時 PCA scores/loadings | PCA 僅用於適當數值表示，說明中心化／縮放 | 說明變異不等於對結果重要；不能只看 2D 就宣告分群 |
| 關係隨時間／批次改變嗎？ | Run chart、批次分面；條件適合再用 ACF／控制圖 | 按時間／批次的摘要與相依性分析 | 時序間隔、重複量測；控制界線不能拿任意資料直接估 |

多維圖優先使用「X、Y + 顏色 + 分面 + 連動框選」，每一維都要有對應問題。
散點矩陣預設只放選中的 3–6 個欄位，可換欄；不輸出幾十欄的圖海。
平行座標與 PCA 留給確有輪廓／維度問題的情境；3D 圖不是預設。

檢定是可選能力，不是每張圖的裝飾。先定義比較量、零假說、觀測獨立性與檢定家族。
獨立組、配對、群聚與時間資料使用不同的推論／重抽樣單位；不以逐列 bootstrap 掩蓋群聚。
顯示效果量、區間、有效樣本數和缺失處置。Mann–Whitney 比較分佈／排序，只有額外形狀條件才可簡化成位置差解讀。
多重檢定選擇有適用條件的 Holm／BH 等方法；資料驅動的選題仍明示為探索，不將校正 p 值當成機制證據。

## 5. 互動證據如何呈現

主要介面仍是 agent 對話；先在對話／Markdown 看建議並選擇，再產出所選分析的 HTML 證據頁。
固定的是分析語意，不是固定四張圖的版面。每項分析可以是單圖、並排對照或多圖連動，agent 選擇時說明理由。

一項已執行分析按以下順序呈現：

1. 研究問題：這次想辨識什麼、為何先做這項。
2. 分析設計：母體、列／個體數、欄位、條件、方法、抽樣及缺失處置。
3. 互動圖組與可下載的計算表。
4. 計算支持的觀察，連到統計產物／圖表資料；分開寫替代解釋與未知。
5. 下一步選項：換比較方式、追查子群、補資料、提出特徵，或停止。

保留全體參考，分清 highlight 與 filter。切換篩選後，不沿用舊統計敘述作新子群結論。
純顯示摘要可即時計算並標示範圍；LOWESS、檢定、PCA 等需重算的層顯示「原分析結果，未隨檢視重算」，或隱藏並提示交 agent 重新分析。
匯出保留 analysis_id、資料 hash、row IDs、篩選、欄位、註記及下一步意圖；接續時驗證版本並建立新分析，不覆寫舊證據。
首版沿用現有 Plotly 離線資源與 HTML；不重新建構 JMP，亦不依賴 CDN 或常駐後端。

## 6. 二手車示例：呈現建議而非捏造結果

以下是設計範例，不是使用者已確認的 brief，也不是新的數據分析結論。

brief 草案：「了解刊登價與使用程度的關係，辨識是否由品牌／車型組成造成，準備一份可解釋的建模候選欄位清單。」
觀測單位暫定刊登紀錄，不假定一列就是一輛唯一車；刊登價不代表成交價。車齡需可靠觀測年份，2020 尚待來源確認。

| 優先 | 建議 | 為什麼 | 若觀察到不同結果，如何改變方向 |
|---|---|---|---|
| 1 | 價格與里程的 ECDF／分佈，加品牌、車型樣本組成表 | 先理解量級、長尾、比較母體與稀疏群組 | 若極端值可能是單位或來源問題，先查資料；若是真實高價車則保留並分層 |
| 2 | 里程×價格散點 + 平滑線，再按品牌／車型分面並核對年份分佈 | 區分總體關係與群組構成造成的差異 | 若總體與群內方向不同，先追查組成與重疊範圍，不能直接宣稱里程效果 |
| 3 | 原始里程與 log1p 里程的關係圖並排 | 檢查轉換是否讓形狀更容易描述，說明其用途 | 若形狀沒有更清楚，可不採用；不因常見做法就加入特徵 |

只有來源年份確認後才建議車齡；mileage／age 對新車分母及使用期間的假設必須先說明，不默認 max(age,1) 合理。
本次不預報哪個因素重要、哪個關係顯著，也不將過去建模分數用作這三項 EDA 的證據。

## 7. 特徵交接與後續模型邊界

人類看到的是逐項清單，涵蓋原始與衍生欄位：名稱、用途、公式／單位、證據 analysis_id、替代解釋、可用時點、風險、採用／暫緩／排除及理由。
探索中可核准試算特徵看關係；試算不代表核准進模型。低邊際相關不自動排除交互作用候選；群組 ID 可用作切分或調整角色，預設不當預測捷徑。
交接記錄白名單與角色：predictor／target／group／time／audit，以及前處理規則、brief 版本、來源版本、人工決定。
允許候選清單為空或只保留原始欄位。被否決／暫緩的特徵仍留紀錄。

後續才確認模型任務、損失函數、主指標、驗證設計、可解釋性約束及搜尋預算。
同一回歸題也需依關係形狀、樣本量、異質性及用途比較線性／正則化、樣條／GAM、樹等候選；本輪不實作選模規則。
未來 Auto Research 的「最佳」只能是約定資料、候選集合、約束與預算內的結果。它不可反覆用封存測試集選演算法，也不能以分數替代本輪的人類研究選擇。

## 8. 薄 skill 的組件與產出

維持一個入口 `.agents/skills/scientific-analysis/SKILL.md`。新增內容按需讀取；以下路徑是未來提案，不是本次已建立的檔案。

| 組件 | 責任與建議路徑 |
|---|---|
| brief 規範 | `references/eda-brief.md`：整理需求、未知與確認，不代替人類決定 |
| 建議方法卡 | `references/eda-methods.md`：問題 → 適用條件 → 圖組 → 方法 → 限制 → 來源 |
| 確定性計算 | `scripts/eda.py`：盤點、執行選定分析、寫出數值／圖資料；不呼叫 LLM |
| 現有渲染組件 | 擴充 `reporting.py` 與 assets，接收每項分析的圖組描述，重用現有資料版本與互動匯出 |
| 人類決定紀錄 | JSON 保存選擇與 provenance；agent 對話負責提案與解釋，不另建規則引擎／排程服務 |

同一份結構化內容衍生 Markdown／HTML，避免數字與文字各維護一份。

| 產出 | 用途 |
|---|---|
| `brief.json` + `brief.md` | 可機讀與可確認的研究問題；draft 不可當 confirmed |
| `data_inventory.json` | 盤點與欄位角色／未知，不含模型分數 |
| `analysis_proposals.json` + `analysis_proposals.md` | 可選分析與推薦理由，含未採用項目 |
| `decisions.json` | 對應版本、選取 ID、選擇者與理由；以新版本保留歷史 |
| `analyses/<analysis_id>/` | 計算表、方法參數、圖資料、敘述及來源 lineage |
| `exploration.html` | 依已執行分析組織的互動證據，可續接研究 |
| `feature_candidates.json` + `.md` | 人類逐項審查的原始／衍生特徵及角色，供後續模型接手 |

每項分析連結 brief_version、proposal_id、資料 hash、使用列／篩選、程式與方法版本、參數及抽樣種子。
brief 或資料版本變更不沿用舊核准；重算建立新 ID，保留父項目。JSON 結構用簡單 schema 驗證，不引進 workflow framework。

## 9. MVP 順序與驗收

第一批先把脈絡做對：brief、資料盤點、3–5 項建議、人類選擇、單一分析執行與證據回訪。
首批實作分佈／ECDF、數值散點與可選 LOWESS、群組 boxplot／分面、Pearson／Spearman、缺失摘要。
第二批才加入效果量與適用的區間／檢定、類別關係、多維散點矩陣、特徵交接；PCA、時間與領域專屬工具後續按真實需求增加。
方法卡明示 supported／proposal-only，未實作方法不得顯示已完成；可建議人工選擇補實作，但不能靜默換成另一種統計方法。

設計採保留舊 CLI 與舊 run 的相容策略，新 EDA 用獨立入口及 schema；舊研究紀錄不得自動標為已確認 brief。
既有模型分數／OOF 產出不改動；原有回歸測試繼續執行。新入口具體命令名由後續實作計畫定稿。

軟體驗收：

- 未確認 brief 只能盤點必要 metadata；正式分析需對應已確認版本及已選 proposal。
- 未選的分析不執行；執行一次選定 EDA 不觸發 features／model。
- 沒有 target 也能完成 EDA；所有敘述標示觀察、假說或限制，研究問題不可冒充 observation。
- 常數欄、空子群、稀疏類別、非有限值與重複量測不輸出誤導性的統計值；有具體原因與替代建議。
- 互動連動／篩選可還原；篩選後舊推論明確失效；HTML 離線可開啟。
- 原始資料不改、封存資料不進 EDA、核准版本／資料 hash 不符則拒絕執行。
- 每項特徵核准可追溯，試算特徵不自動進入建模白名單。

研究體驗驗收：用現有二手車素材做一輪真實對話，讓資料科學家在執行前看見「為何分析、有哪些備選、會改變什麼決定」，能拒絕一項建議、選擇另一項，並依證據提出下一問。
這項人類驗收不能用 pytest 通過或 HTML 存在代替。首輪成功不宣稱覆蓋 80% 題目。
