# 分析角色的證據契約

每個角色直接產生目前專案需要的文件，連到實際資料、程式與結果。角色名稱代表責任，不要求把所有環節跑完。

| 角色 | 需要的內容 | 產出與必要問題 |
| --- | --- | --- |
| ds-frame | 需求、Schema 與領域背景 | research/question.md 記問題與人類確認；plan.md 記假設、反證、推薦順序與驗證設計 |
| ds-proxy | 已確認問題、計畫與欄位 | research/proxy.md 記缺少概念、替代訊號、理由、單位、可取得性、混雜與驗證 |
| ds-eda | 問題、計畫、資料與假設 | reports/explorations/<輪次>/eda.md 記品質、方法、效果量、樣本、不確定性、多重比較、反證與重現方式 |
| ds-rules | 分析發現及可採行動 | reports/rules.md 記候選條件、範圍、驗證、涵蓋率、誤報漏報、處置與退出條件 |
| ds-impact | 分析發現與成本來源 | reports/impact.md 記觀測與假設、共同期間、公式、情境、敏感度及損益兩平 |
| ds-review | 實際報告與相關計算 | reports/review.md 記審查對象、來源、具體問題、嚴重程度與修正狀態 |
| ds-deliver | 已有證據與審查結果 | reports/decision.md 回答決策，研究交接文件說明限制與下一步 |

只有 Schema 時可以交付定義或假設提案，未執行的統計分析不能寫成已完成。代理特徵、規則與效益分析依需求選用，不為填滿流程硬做。

每項主要主張連到其實際來源、資料範圍、方法與計算輸出；需要區分版本時使用日期、檔名、Git commit 或雜湊。方法參考與骨架見 [技能參考與模板](skill-resources.md)。

問題確認代表同意研究邊界，領域合理性、獨立驗證與介入成效仍需各自證據。審查依實際內容判斷，模板填滿、角色切換或檔案存在都不能替代驗證。
