# Kaggle 適用性與第三方視角評估

查核日期：2026-10-30。這是獨立代理審查加官方文件核對，不是真人第三方認證，也不是競賽實跑結果。

**不能承諾任何 Kaggle 專案都能跑。** 本架構可共用問題、證據、實驗與交付管理；能否執行仍取決於題型 adapter、資料權限、資源、規則及平台介面。技能是工作規約，目前不是內建所有 loader／模型／評估器的執行引擎。

| 題型 | 架構可共用部分 | 額外條件／限制 |
| --- | --- | --- |
| 表格分類／回歸 | 問題、EDA、特徵、模型比較、報告 | 優先驗收範圍；仍需逐題 metric、ID 與提交格式 |
| 時序／群組／排序 | 同一實驗與證據管理 | horizon、群組隔離、query 單位與專用 metric |
| 影像／文字／音訊／多模態 | 任務規劃、預算、實驗、審查 | 專用 loader／模型資產、GPU、記憶體、授權與推論成本 |
| Code Competition | pipeline 與交付管理 | 官方 notebook 模板、平台重跑、網路與時間限制 |
| Package 交付 | 訓練與推論契約 | 官方 Model／predict 介面、依賴與隱藏資料推論 |
| 模擬／互動代理 | 問題與版本管理 | 環境協定、episode、執行封裝；不能套一般表格流程 |
| 人工評審／hackathon | 分析與報告 | rubric、展示及 writeup，不一定有單一評估指標 |

此矩陣是適配判斷，不是已測支援清單。Kaggle 的競賽交付與限制依題目而異，需讀該題規則及 evaluation 頁；public leaderboard 不取代獨立驗證。[官方 Competitions](https://www.kaggle.com/docs/competitions)

Package 也是需考慮的交付介面，不能把提交 schema 寫死為 CSV／notebook 二選一。[官方 Packages](https://www.kaggle.com/docs/packages)

## 如何讓大多數題目可以接入

採六份契約，寫入現有研究與設定文件，不增加六個必跑 skill：任務、資料、執行、驗證、實驗、交付。詳細欄位見 [任務契約](../skills/_shared/references/task-contract.md)。

每題開始先判斷 `ready / needs-adapter / blocked`，附具體缺口。adapter 僅處理可變部分：資料讀取、任務 metric、驗證單位、推論入口與提交格式；研究與證據管理沿用共同流程。

先完成小樣本 smoke run，再做可解釋基準與一次完整推論，最後才投入搜尋。交付依次驗收：本機 schema 正確、能重新載入、平台接受、平台成功評分。通過前一步不代表後一步通過，也不保證競賽名次。

官方 CLI 可支援下載、notebook 與提交操作，但工具存在不等於本套件已接好，也不代表使用者已授權接受規則或對外提交。[Kaggle CLI](https://github.com/Kaggle/kaggle-cli)

## 必須避免的失敗模式

- 公開榜調參過度：保留固定本地驗證與試驗紀錄；不把最佳公開分數當最終泛化表現。
- 不符合場景的切分：同人多筆、時間先後、query 群組需逐題判斷，不能預設 random split。
- 能訓練卻不能提交：開始時就檢查模型資產、斷網依賴、推論時間與交付介面。
- 可重現假象：只存 seed 不夠，還需資料、程式、環境、設定與產物版本；某些硬體計算仍有非確定性。
- 規則或權限阻擋：外部資料、預訓練模型、網路、運算與提交額度不可寫成全域常數。
